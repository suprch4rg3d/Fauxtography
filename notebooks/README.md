# Notebooks - results & verdicts

The **analysis layer** of the project lives here. These are the notebooks you
open in Google Colab (or locally) to inspect results, document the manual
error inspection, and write the verdicts that go on the presentation slides.

| Notebook | Purpose | Owner |
|----------|---------|-------|
| `fauxtography-on-colab.ipynb` | **run first** in Colab: env, Drive, data split, training - everything in one notebook | shared |
| `00_data_overview.ipynb` | confirm splits + class balance, sample grid | shared |
| `analysis_clip.ipynb` | CLIP metrics, confusion matrix, error inspection, verdict | DemetraP20 |
| `analysis_dinov2.ipynb` | DINOv2 probe metrics, errors, verdict | suprch4rg3d |
| `final_report.ipynb` | side-by-side comparison + joint conclusions | both |

## Running in Colab (with a GPU)

1. **Open `fauxtography-on-colab.ipynb` first** and run its cells
   top-to-bottom: it
   installs a Python 3.14 env with `uv`, installs the package, verifies the
   accelerator with `fauxtography env`, splits the dataset, and runs the model
   commands. Outputs go to your Drive via `FAUXTOGRAPHY_*` env vars, so they
   survive Colab session disconnects.
2. Then open `00_data_overview.ipynb` and the per-model analysis notebooks.
   `analysis_dinov2.ipynb` locates `results/` on its own (walks up from the
   notebook path), so it works from the repo root, from `notebooks/`, or in
   Colab - no manual path pointing.
3. Run the analysis notebooks top-to-bottom. They read the metrics committed
   under `results/` and draw the figures inline; if a `results/<model>/` is
   missing, they print a short message.

## Template-generated vs hand-maintained

- `fauxtography-on-colab.ipynb`, `00_data_overview.ipynb` and
  `final_report.ipynb` are generated by `scripts/make_notebooks.py`. Edit the
  templates in `scripts/make_notebooks.py` and re-run `python
  scripts/make_notebooks.py` from the repo root to rebuild them. **Don't edit
  the generated JSON by hand.**
- `analysis_clip.ipynb` and `analysis_dinov2.ipynb` are **hand-maintained**:
  their content and figures live directly in the `.ipynb`. The generators for
  them are commented out in `make_notebooks.py` so regeneration never silently
  replaces the written-up analysis.

## Conventions

- Commit the *notebooks*, not their outputs. Clear outputs before committing
  to keep diffs reviewable; the notebooks read results from disk.
- Verdicts: one sentence per finding. The fuller DINOv2 write-up lives in
  the analysis notebook itself (`notebooks/analysis_dinov2.ipynb`).
